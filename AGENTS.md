# Руководство для AI-агентов

## Обзор проекта

`boxing` — клиентское React-приложение BOX-PROFILE для комплексного профилирования боксеров и индивидуализации подготовки. Интерфейс на русском языке. Приложение хранит данные спортсменов, групп, тестов и заметок локально в браузере через `localStorage`; серверная часть и API отсутствуют.

Основной интерфейс включает:

- соревновательный профиль с учетом ударов по раундам, таймером, расчетом плотности боя, точности, КЭУ/КВ, графиками и архивом боев;
- морфофункциональный профиль с вводом показателей состава тела, анаэробной и аэробной производительности, СФП и психомоторики;
- экспертный модуль определения стиля и коррекции на основе физиологических данных и исследовательской базы;
- экспортируемый/печатаемый научно-методический отчет;
- вкладку нормативов и стандартов бокса с фильтрацией документов.

## Технологический стек и конфигурация

- React 19 и React DOM 19, функциональные компоненты и хуки.
- Vite 8 как dev-сервер и сборщик; `@vitejs/plugin-react`.
- Tailwind CSS 4 через плагин `@tailwindcss/vite`; основной импорт стилей находится в `src/index.css`.
- `lucide-react` для иконок, `recharts` для графиков, `html2pdf.js` для создания PDF.
- JavaScript/JSX ES-модули (`"type": "module"` в `package.json`); TypeScript не используется.
- `package.json` и `package-lock.json` фиксируют зависимости и команды.
- `vite.config.js` подключает React-плагин и Tailwind-плагин.
- `.oxlintrc.json` включает плагины `react` и `oxc`, проверку правил хуков и предупреждение для компонентов, экспортирующих некомпонентные значения.
- `index.html` задает корневой элемент `#root`, подключает `src/main.jsx`, манифест и заголовок приложения.
- `public/manifest.json` содержит PWA-метаданные, standalone-режим и темную цветовую схему.
- `.gitignore` исключает зависимости, `dist`, локальные файлы, логи и файлы IDE.

## Запуск, сборка и проверка

Из корня проекта:

```bash
npm install
npm run dev
npm run lint
npm run build
npm run preview
```

- `npm run dev` запускает Vite с горячей перезагрузкой.
- `npm run lint` запускает Oxlint.
- `npm run build` создает production-сборку в `dist/`.
- `npm run preview` локально обслуживает уже собранную production-версию.
- `npm test` запускает `node --test "tests/*.test.js"` — тесты чистых модулей `src/data` и `src/utils`, где `localStorage` подменяется стабом. Отдельного test runner-пакета и CI-конфигурации нет. После изменений следует запускать lint, тесты и production build; поведение интерфейса проверяется в браузере через dev-сервер или preview.
- `npm run validate:research-staging` запускает `scripts/validate-research-staging.mjs` — проверку целостности staging-пакета `data/research-staging/BOX_PROFILE_normalized_import` (JSON, счётчики манифеста, уникальность ID, ссылки, статусы проверки, происхождение). Скрипт только читает пакет; расхождения выводятся как ошибки с кодом выхода 1. Пакет не является нормативной базой и в `src/data` не импортируется.

Собранное приложение является статическим фронтендом: для публикации используется содержимое `dist/` на статическом хостинге с поддержкой SPA-маршрутизации при необходимости. Backend, миграции, секреты, переменные окружения и отдельный deployment pipeline отсутствуют.

## Runtime и организация кода

Поток запуска:

1. `index.html` загружает `src/main.jsx`.
2. `src/main.jsx` импортирует глобальные стили и монтирует `<App />` в `#root` внутри `StrictMode`.
3. `src/App.jsx` хранит состояние активной вкладки, групп и выбранного спортсмена, синхронизирует группы/спортсменов с `localStorage`, управляет добавлением и удалением и передает выбранного спортсмена дочерним представлениям.
4. В зависимости от вкладки `App.jsx` отображает один из модулей `src/components/`.

### Основные модули

- `src/App.jsx` — действующий корневой компонент приложения и навигация между пятью вкладками. Использует ключи `box_groups` и `box_athletes` в `localStorage`.
- `src/components/BoxDataView.jsx` — соревновательные данные, раунды, таймер, расчет показателей, Recharts-графики, сохранение истории боев и экспорт CSV.
- `src/components/PhysTestView.jsx` — форма морфофункциональных тестов; данные спортсмена сохраняются под ключом `box_phys_<id>`.
- `src/components/MatrixView.jsx` — расчет стиля, асимметрии и лимитирующих факторов по данным физического профиля; фильтрует научную базу.
- `src/components/ResearchDatabaseView.jsx` — вкладка «База исследований»: просмотр встроенных и пользовательских записей, форма добавления с валидацией, допуск к сравнению, экспорт и импорт пользовательской базы через JSON-файл.
- `src/components/ReportView.jsx` — отчет, заметки тренера, печать и PDF-экспорт через `html2pdf.js`.
- `src/components/StandardsTab.jsx` — фильтрация и отображение нормативно-правовых документов.
- `src/components/AthleteProfileView.jsx` — вспомогательное представление для альтернативной реализации приложения.
- `src/data/boxingStandards.js` — документы и конфигурация этапов подготовки с возрастами, годовыми объемами и соотношениями видов подготовки.
- `src/data/researchDatabase.js` — встроенные записи научно-исследовательской базы; `getAllResearch()` объединяет их с пользовательскими.
- `src/data/userResearchStore.js` — хранение пользовательских записей в ключе `box_research_user`, валидация и нормализация, экспорт базы в JSON-строку, разбор, предпросмотр и импорт файла (режимы `merge` и `replace`).
- `src/data/modelsConfig.js` — каталог показателей, статусы достоверности, референтные модели и правила допуска к сравнению.
- `src/utils/athleteNormsChecker.js` — выбор конфигурации нормативов по возрасту спортсмена.
- `src/index.css` — единственный глобальный CSS-файл, импортирующий Tailwind CSS.
- `src/App.css` и `src/assets/` содержат оставшиеся шаблонные/дополнительные ресурсы; текущий `main.jsx` импортирует только `index.css`.
- `public/` содержит manifest и публичные ресурсы.

`src/App.js` — отдельная более ранняя реализация с простым профилем и базой документов. Текущий entrypoint импортирует `App.jsx`, поэтому при изменениях основного приложения следует работать с `App.jsx`, если задача специально не требует обновления legacy-файла.

## Хранение данных и границы приложения

Состояние не передается на сервер и не синхронизируется между устройствами. Ключи `localStorage` включают `box_groups`, `box_athletes`, `box_fights_history_<athleteId>`, `box_phys_<athleteId>`, `box_coach_note_<athleteId>` и `box_research_user`. Компоненты повторно загружают данные при смене спортсмена. При работе с новыми полями необходимо сохранять привязку к `athlete.id` и учитывать отсутствие или повреждение сохраненного JSON. Пользовательская база исследований переносится между устройствами файлом JSON (экспорт/импорт во вкладке «База исследований»): импорт принимает только поля схемы записи и отклоняет то, что не прошло валидацию, не изменяя хранилище. Остальные данные файлом не переносятся.

## Соглашения разработки

- Используйте функциональные React-компоненты, `useState`/`useEffect` и именованные обработчики событий в стиле существующих компонентов.
- Новые компоненты и экраны размещайте в `src/components/`; статические предметные данные — в `src/data/`; чистые вспомогательные функции — в `src/utils/`.
- Для внешнего вида используйте Tailwind utility-классы в JSX; существующая тема — темная палитра Slate/Blue/Amber/Emerald.
- Сохраняйте русские подписи интерфейса и комментарии, если изменяете соответствующие участки. Не добавляйте отдельную систему локализации без необходимости.
- Соблюдайте существующий формат JavaScript/JSX. В большинстве компонентов используются точки с запятой, тогда как bootstrap-файлы частично используют стиль без них; при изменении файла придерживайтесь его локального стиля.
- Не добавляйте зависимости без необходимости: сначала проверьте `package.json` и lock-файл.
- После изменений проверяйте правила Oxlint, особенно корректное использование хуков React.

## Проверка перед завершением работы

1. Запустите `npm run lint` и устраните ошибки.
2. Запустите `npm run build` и убедитесь, что production-сборка создается.
3. Запустите `npm test` — тесты покрывают модули данных и анализатор, в том числе экспорт и импорт базы исследований.
4. Для изменений UI вручную проверьте сценарий в `npm run dev` или `npm run preview`, включая добавление спортсмена, переключение вкладок, экспорт/импорт файла и сохранение данных в браузере.
5. Не рассчитывайте на backend или CI: их в проекте нет.
