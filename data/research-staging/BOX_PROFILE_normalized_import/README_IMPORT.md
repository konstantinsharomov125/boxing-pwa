# BOX-PROFILE — нормализованный пакет подготовки научных данных

Версия пакета: 0.1.0  
Дата подготовки: 2026-10-19  
Статус: **staging / не production**

## Цель
Преобразовать две исходные Excel-книги в предварительно нормализованные связанные записи, сохраняя исходные поля и происхождение каждой строки. Пакет предназначен для ревью и последующего импорта в BOX-PROFILE, а не для непосредственного использования как нормативной базы.

## Состав
- `data/studies.json|csv` — 31 запись исследования из основного реестра.
- `data/cohorts.json|csv` — 31 описание популяции на уровне исследования; они не считаются окончательно структурированными отдельными когортами.
- `data/protocols.json|csv` — 31 сводка методов из поля Methods. Это контекст уровня исследования, не подтверждённый точный протокол каждого измерения.
- `data/observations.json|csv` — 216 строк результата, с исходными статистиками, единицами и локаторами.
- `data/metric_candidates.json|csv` — 106 кандидатов показателей по точной комбинации исходной области, названия и единицы. Они не сопоставлены автоматически с `METRICS_CATALOG`.
- `data/model_candidates.json|csv` — 116 строк из таблицы модельных характеристик; значения сохранены как исходный текст с безопасными подсказками для ручного разбора.
- `data/external_source_candidates.json` — 20 библиографических кандидатов из второго файла.
- `data/source_reconciliation.csv` — предложенные связи со Study из основного реестра, включая конфликты года.
- `data/review_queue.json|csv` — список элементов, требующих проверки.
- `data/field_mapping.json|csv` — карта преобразования полей.
- `data/import_manifest.json` — счётчики и предупреждения.
- `source_files/` — точные копии двух исходных Excel-книг.
- `reports/` — краткое резюме проверки.

## Ключевые ограничения
1. В рамках этого преобразования публикации и числовые значения **не проверялись заново по полным текстам**.
2. Ни один числовой результат не допущен к нормативному сравнению; количество новых reference models = 0.
3. Структурированное поле `Value` первого Excel сохранено как оно было в исходной ячейке. `SD`, `Min`, `Max`, `Statistic_type` отдельно сохраняются по исходным колонкам.
4. Для свободного текста в `Числовые данные` второго Excel исходная строка сохраняется неизменно. Если найден шаблон `число ± число`, числа обозначаются только как `candidateCentralValue` и `candidateDispersion`; тип разброса не назначается без проверки первоисточника. Несколько чисел с `/` и другие сложные строки не превращаются автоматически в наблюдения.
5. Совпадения DOI/URL/названий во втором Excel являются кандидатами на связь, не молчаливым объединением. Два конфликта года помечены.
6. `MetricCandidate` — это предварительный словарь строковых названий, а не окончательная научная онтология. Семантически похожие показатели могут оставаться разными, пока специалист их не сверит.
7. Все наблюдения имеют `verificationStatus = not_reverified_during_normalization` и `numericalUseStatus = not_approved_for_reference_model`.
8. Никакие записи не загружены на GitHub, Vercel, Supabase или в production-данные приложения.

## Рекомендуемый процесс утверждения
1. Сохранить архив этого staging-пакета.
2. Проверить `source_reconciliation.csv` и подтвердить или отклонить предложенные связи с основным реестром.
3. Разобрать `review_queue.csv`, особенно множественные значения, запись `±`, отсутствующий `Value` и конфликтующие годы.
4. Сверить `metric_candidates.csv` со словарём `METRICS_CATALOG` и создать явную карту `metricCandidateId -> metricId` только после экспертного решения.
5. Сверить числовые значения с первоисточниками и заполнить точные страницы/таблицы/рисунки.
6. Только после ревью сформировать application import package и тестировать импорт на копии данных.
7. Не использовать кандидатные значения как нормы, пока отдельное решение не допустит соответствующие observations/reference models.

## Почему значения не объединены автоматически
Публикации могут описывать разные выборки, группы, руки, удары, протоколы и статистики. Сохранение исходного значения и источника важнее, чем преждевременная унификация. Автоматическая обработка здесь только создаёт кандидатов на ручную проверку.
